Two desktop-specific findings remain open:

1. **Default HiDPI scaling is wrong on this configuration.** Hyprland has `xwayland:force_zero_scaling=true`; the
   application draws at approximately 100% despite the physical monitor being configured for 200% (and inherited
   `GDK_SCALE=2`). Native Meld scales correctly. The explicit Avalonia scale override works, but automatic scaling
   needs a fix with a regression that accounts for compositor/XWayland scale ownership. Do not change the user's
   compositor configuration to hide the problem. Evidence: `screenshots/02-main.png`, `04-settings.png`,
   `08-meld-wayland.png`, `13-scaled.png`, and the monitor/window JSON in `logs/`.
2. **Clipboard MIME-format interoperability:** after copying commit `1781e0b06c20d6af712a5c90f7925c4369169465`,

   Exact original output is in `logs/clipboard-formats.txt`.

## Fixes and Hyprland recheck (2026-09-26)

Scratch evidence: `/tmp/ge-linux-fixes-20260926` (portable app copies, separate HOME/all writable XDG roots,
private D-Bus started after exporting that environment, scratch clone, screenshots and logs).

- **First-run language:** `Program.RunApplication` saves startup choices before constructing the checklist's
  independent settings containers. With fresh portable settings on Hyprland, choosing English immediately showed
  "The configured language is English" in the checklist. Save and rescan, OK and a normal restart retained English
  and telemetry disabled; the language prompt did not recur. This is a manual regression check
  (`03-checklist.png`, `05-restart.png`), not an automated startup test.
- **Clipboard to native Wayland clients:** the app returned correct `text/plain` bytes to X11 clients even before
  the fix. Hyprland 0.56.2's `CXWM::mimeToAtom` maps a Wayland `text/plain` request to the X11 `TEXT` atom, which
  Avalonia 12.1.3's text formats omit. The Linux copy helper now offers UTF-8 bytes for `TEXT` alongside the normal
  Avalonia text formats. Revision-grid Ctrl+C, shared copy commands/context menus and dialog-message copies use it;
  Windows/macOS keep the existing clipboard path. Actual desktop checks copied a commit hash with Ctrl+C and
  `Žąsis 日本語 😀` plus a second paragraph through the context menu. Default `wl-paste`, explicit Wayland
  `text/plain`/UTF-8 and X11 `TEXT`/UTF-8/`text/plain` all returned identical, complete content. Exact outputs:
  `logs/clipboard-app.json`, `logs/clipboard-final-hash.json`, `logs/clipboard-final-unicode.json`.
  This workaround does not replace Avalonia's built-in TextBox/editor selection-copy implementation or add a native
  Wayland backend; those paths remain outside this fix. Upstream source inspected:
  [Hyprland 0.56.2 XWM](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/xwayland/XWM.cpp),
  [Avalonia 12.1.3 text atoms](https://github.com/AvaloniaUI/Avalonia/blob/12.1.3/src/Avalonia.X11/X11Atoms.cs).
- **Async UI test failures:** the headless test helper selected `Dispatch(Func<TResult>)` with `TResult = Task`,
  returning a nested task without awaiting the test body. It now dispatches an awaited body with a scalar result.
  A regression verifies that an exception after an asynchronous continuation reaches the runner. With this corrected
  harness, all three new clipboard cases (empty, hash, Unicode/multiline) failed before the clipboard fix and passed
  after it. The existing asynchronous paste/edit test also passes with its assertions now reliably observed.

The final Release solution build passes with five existing Avalonia placeholder-property warnings. All 18 test
project invocations pass sequentially with `--blame-hang-timeout 3m`: **25,320 passed, 0 failed, 167 skipped**.
Windows/macOS were not rerun. Default HiDPI scaling, native Wayland support and the other open findings above remain
unresolved. Test windows/private services were stopped, workspace 1 restored, and the real Git configuration hash
remained unchanged. No additional software was installed in this fix pass.
