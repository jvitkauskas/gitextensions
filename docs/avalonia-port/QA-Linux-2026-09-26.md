## Fixes and automated validation

1. **Arch Zed discovery:** the editor list only searched for `zed`, while Arch installs `zeditor`. Linux now offers
   `zeditor --wait` when `zed` is absent, prefers `zed` when both exist, and preserves macOS behavior. Three added
   regression cases cover those choices. The Arch case failed before the fix; all five editor-discovery tests pass
   afterwards. The rebuilt UI shows the new entry and the command completed a real commit edit.
2. **First visible diff line at fractional heights:** the baseline Avalonia suite reproducibly reported line 40
   where line 41 had been scrolled exactly to the top. The measured offset and line 41's visual top were both
   `693.6210937499998`; the height-tree lookup rounded into the preceding line. The lookup now uses a tiny epsilon
   at the boundary. The first-change scrolling regression covers font sizes 11, 12.5 and 13.3. Targeted tests pass.
   Installing DejaVu alone did not fix the original failure. This numerical boundary was verified headlessly;
   the rebuilt app's ordinary diff/merge views were also exercised.

After both changes, the Release build and all **18 test-project invocations** succeeded, run sequentially with
`--blame-hang-timeout 3m` and an outer watchdog. TRX totals: **25,316 passed, 0 failed, 167 skipped** (total minus
executed; the Windows-only UI integration assembly has no executed cases). The separate Secret Service opt-in
test also passed once the scratch keyring was created/unlocked. Its first attempt lacked a default unlocked
collection and was a fixture failure. `git diff --check` passed.

## Open findings and remaining coverage

- **First-run language persistence:** with fresh portable settings, choose English, then save through the startup
  checklist. The checklist can still say no language is configured, and the next launch asks again. The choice is
  assigned in memory by `TryShowChooseTranslation`; `CommonLogic` creates a fresh global settings container from
  disk before the settings dialog saves. This is the likely loss boundary. It needs a persistence regression and a
  deliberate fix to startup/settings ownership. Choosing English again once the checklist no longer opens did
  persist. Evidence: `02-startup.png`, `25-after-language.png` and the original portable settings.
- **Unexpected custom difftool:** the app's configured-tool dropdown filters platforms correctly, but the diff
  context menu also parses `git difftool --tool-help`. It offered Araxis on Linux, where ImageMagick supplies a
  `compare` executable. Araxis was not installed or executed. Review `CustomDiffMergeToolCache` and preserve
  explicitly configured user tools when deciding how to filter this list. Evidence: `14-diff-tools.png`.
- **Menu remains above modal dialogs:** observed when opening Statistics, Gource, Clone and Create branch from
  menus on X11/Openbox. Escape dismisses the old menu and exposes the dialog. Needs a menu/modal event-order
  regression; do not infer a safe shared-platform fix from coordinate automation alone. Evidence: `74-statistics.png`
  (after dismissal), `75-gource.png`, `78-clone.png`.
- **Dark hyperlink contrast:** commit-detail links remain dark blue against dark gray, making them difficult to
  read. The rest of the inspected dark controls and diff text were readable. Evidence: `58-dark-main.png`.
- The SSH page still contains explanatory text recommending PuTTY for Windows users even though its Windows-only
  controls are hidden on Linux (`93-ssh-settings.png`).
- Not exercised manually: separate fetch with new upstream changes; SSH host-key/HTTPS authentication and pushes;
  rebase/cherry-pick/revert/reset; stash; tag creation; remote prefix/color editing; submodule/worktree creation;

## Isolation and cleanup

The real Git config remained byte-for-byte unchanged (SHA-256
`c13840001af4a4654f5684a0b06d4444e4e66ee98c62e3154eb9061e4280358f` for `~/.config/git/config`);
`~/.gitconfig` remained absent. Git Extensions settings were portable and repository mutations stayed in scratch
repositories, apart from the requested source fixes, documentation and initialized submodules.

There was an isolation mistake in the external-tool setup: the private bus was initially started before exporting
scratch HOME/XDG paths, so its first autoactivated dconf helper inherited the real config path. The real
`~/.config/dconf/user` was rewritten during the Meld run. In addition, inherited `XDG_STATE_HOME` caused writes to
real `~/.local/state/kdiff3staterc`, `katestaterc`, `UserFeedback.org.kde.kate` and `lesshst` during testing. The bus
activation environment and scratch environment were corrected, but no pre-run baseline exists for those preference
files. They were not blindly reset or deleted. This run therefore **cannot claim complete desktop-preference
isolation**. Early portal/GVfs helpers also inherited real HOME, so their metadata was not established unchanged.
The native-Linux instructions now explicitly cover both traps.

The Secret Service daemon used scratch HOME from its start; the credential test used its private bus. No real
credential entry was created. Scratch credential collections were checked empty, and the disposable SSH agent's
key was removed before stopping the agent. Test applications, external helpers, private bus, keyring, Openbox and
both Xvfb servers were stopped. Installed packages and the scratch evidence/tool directory were retained.
